# 판별 대상과 검증 방법

이 프로젝트는 AI Hub 금융거래 합성데이터의 `이상거래여부`를 예측합니다. 출금액만으로 사기를 확정하거나 모든 예외 상황을 탐지하는 모델은 아닙니다. 유형별 라벨은 전문·다중분류 모델의 학습 정답과 유형별 평가에 사용하며, 거래를 판별할 때 입력하지 않습니다.

## 입력과 과거 이력

이체 입력은 거래일자, 출금·입금 계좌와 금융회사, 금액, 3시간 단위 시간대, 자금 종류, 이체 방식의 9개 필드입니다. 계좌·금융회사는 서버가 과거 기록을 연결하는 키이며 식별자 문자열을 학습 특징에 넣지 않습니다.

기존 맥락 경로는 거래일 이전 최근 90일 상세 기록과 전체 과거 누적 통계로 36개 특징을 계산합니다. 입출금 흐름 연구 경로는 66개 특징을 사용하며, 출금계좌의 과거 입금, 수신계좌의 입출금과 송금자 수, 당일 이전 시간대와 최근 24시간의 출금도 반영합니다. 계좌 키는 `(금융회사, 계좌)`입니다.

[공식 데이터 안내](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71925)의 2026년 7월 30일 활용 가이드에서 이체 시간대는 00~02시, 03~05시 등으로 정의됩니다. 같은 시간대 안에서는 실제 거래 순서를 알 수 없어 그 시간대의 다른 거래를 과거로 넣지 않습니다. 카드의 시간 단위 이력도 같은 시간 안의 거래를 제외합니다. 시간창 경계에는 원본 시간 해상도의 한계가 남습니다.

Kotlin 서버가 저장 원장에서 이력을 읽고, Python은 학습과 API에서 같은 특징 계산 모듈을 사용합니다. 20,000건이나 요청 크기 제한을 넘긴 상세 이력을 조용히 잘라 쓰지 않고 오류로 반환합니다. 로컬 기록이 실제 계좌의 전체 이력을 보증하지는 않습니다.

## 학습과 평가

전체 과거 실험은 학습·검증 파티션을 실제 거래 시점으로 합칩니다. 일반 모델은 2023년 3분기까지 전량을 학습하고 2023년 4분기를 개발 구간으로 둡니다. 동시 거래 전문 모델과 다중분류 후보는 2022년 3분기까지 학습하고 2022년 4분기에서 후보나 경보 기준을 결정합니다. 개발 구간에는 동시 거래나 심야·새벽 대량 거래가 없는 경우도 있어, 한 분기만으로 전체 유형의 성능을 확인할 수 없습니다. 전체 과거 재학습 결과는 이 분할 실험과 별도로 기록하며, 개발 구간에서 고정한 기준을 2024년 정답으로 다시 조정하지 않습니다.

2024년 두 파티션의 원시 거래를 시점순으로 처리해 앞선 이력을 반영합니다. 미래 거래와 정답은 특징에 들어가지 않습니다. 공식 검증 파티션과 2024년 전체 후향 평가를 구분합니다. 이미 반복 열람한 2024년 결과를 새로운 독립 시험으로 주장하지 않습니다.

카드의 원본 누적매출·전월 집계에는 승인 시점 기준이 충분히 확인되지 않은 열이 있습니다. 해당 열을 사용하는 후보와 원시 거래에서 과거 이력을 직접 계산하는 후보를 별도로 기록합니다. 지표가 높다는 이유만으로 시점이 불명확한 입력을 실시간 모델에 채택하지 않습니다.

보고서에는 행수, 설정, 특징, 경보 기준, 파일 해시, 정탐·오탐·미탐, 유형별·분기별 성능, 동액 거래와 이력 제거 비교를 남깁니다. 정상 거래가 대부분인 데이터에서 전체 정확도만 표시하지 않습니다. 정밀도는 경보 중 이상 라벨의 비율이고, 재현율은 전체 이상 라벨 중 탐지한 비율입니다.

## 전체 과거 재학습 결과

이체는 2024년 이전 두 파티션의 **3,002,406건**, 카드는 **1,482,969건**을 모두 사용해 최종 후보를 다시 학습했습니다. 후보 설정과 경보 기준은 과거 개발 구간에서 고정했습니다. 재학습에 포함된 개발 구간의 점수를 독립 검증 성능으로 제시하지 않습니다.

| --- | ---: | ---: | ---: | ---: |

| 이체 3시간 구간 종료 후 · 전체 과거 재학습 | 1,431,700 | 77.66% | 71.31% | 4,732 / 1,361 / 1,904 |

거래 직후 이체 후보는 전량 재학습 전 후보보다 재현율이 낮아 기존 연구 경로의 모델을 자동 교체하지 않았습니다. 카드 후보도 실시간 이력 저장 경로에 연결하지 않았습니다. 학습 완료와 서비스 적용은 구분합니다.

카드 전자상거래 유형은 325건 중 17건만 탐지했습니다. 거래 직후 이체 후보의 분할 거래는 732건 중 87건, 동시 거래는 564건 중 3건이었습니다. 전체 이상 라벨을 대상으로 정밀도 90%, 재현율 80%, 관측된 각 유형 재현율 50%라는 연구 목표를 모두 만족하는 후보는 없습니다. 동시 거래 전문 모델은 해당 유형만 대상으로 정밀도·재현율 목표를 통과했으며, 전체 이체 탐지 성능으로 바꿔 제시하지 않습니다. 이 목표는 프로젝트의 검증 기준이며 금융권 운영 기준이 아닙니다. [준비 상태 검사](../reports/model_readiness.json)는 평균 성능과 유형별 미탐을 함께 확인합니다.

## 구간 종료 후 점검

거래 직후에는 같은 3시간 구간의 거래 순서를 알 수 없습니다. 구간이 끝난 뒤에는 해당 구간에서 관측된 거래 전체를 함께 점검할 수 있습니다. 이 별도 모델은 과거 66개 특징에 같은 구간의 거래 건수·총액·금액 분산·동액 반복·수신자와 송신자 수·역방향 이체 등 20개를 추가한 **86개 특징**을 사용합니다. 현재 거래와 같은 구간의 다른 거래를 포함하므로 즉시 판별 모델의 성능 개선으로 혼동하지 않습니다.

전체 2024년 평가에서 분할 거래는 678/732건(92.62%), 동시 거래는 131/564건(23.23%)을 탐지했습니다. 동시 거래 성능은 여전히 부족합니다. 2023년 4분기 개발 구간에는 동시 거래 유형의 이상 라벨이 없어, 해당 유형이 있는 2022년 4분기에서도 별도 시간 분할과 유형별 학습 가중치를 비교했습니다. 가중치를 적용하자 해당 분기 동시 거래 탐지는 109/271에서 125/271로 늘었지만 전체 경보 정밀도는 68.93%에서 57.89%로 떨어졌습니다. [추가 실험](../reports/bank_window_balanced_experiment.json)의 최종 후보도 정밀도 79.38%·재현율 69.77%로 개선과 손실이 함께 있어 기존 연구 경로를 교체하지 않았습니다. 2024년 정답으로 기준을 맞추지 않았습니다.

[원본 관측 감사](../reports/bank_pattern_evidence_audit.json)에서 2024년 이전 이상 라벨 10,539건은 모두 200만 원 이상이었습니다. 정상 거래 중에도 같은 출금계좌가 같은 3시간 구간에 이체한 행은 528,786건이었습니다. 이 데이터에서는 금액·빈도 하나만으로 이상을 정의할 수 없으며, 낮은 금액의 이상 사례를 학습한 것으로 주장할 수도 없습니다. 아홉 원시 입력이 완전히 같은데 이진 정답이 다른 사례는 이번 감사에서 발견하지 못했습니다.

서버는 저장 원장과 거래 당시의 과거 특징을 읽습니다. 모델의 구간 관측값 20개를 서버가 독립적으로 계산해 대조하고 결과를 별도로 저장합니다. 같은 구간의 재요청은 저장된 결과를 반환합니다. 점검을 완료한 구간에 새 거래를 추가하면 결과가 입력과 달라지므로 HTTP 409로 거부합니다. 이 기능이 처리하는 범위는 로컬 원장에 관측된 거래이며, 실제 금융기관의 전체 거래 수집을 보장하지 않습니다.

### 동시 거래 전문 모델

동시 거래 유형이 존재하는 2022년 4분기를 개발 구간으로 두고, 그 이전 거래 전체로 두 특징 조합을 비교했습니다. 절대 금액을 제외한 16개 구조 특징 후보와 현재 거래 조건·같은 구간 관측값 26개 후보를 비교한 결과, 후자를 개발 PR-AUC로 선택했습니다. 전문 모델의 정답은 이상 라벨이면서 동시 거래 유형인 행입니다. 정답 유형과 계좌 식별자는 판별 입력에 넣지 않습니다.

개발 경보 정밀도 95% 이상, 모델 점수 0.5 이상이라는 조건을 먼저 고정하고 재현율이 가장 높은 기준 0.694534를 선택했습니다. 이후 2024년 이전 **3,002,406행 전부**로 재학습했습니다. 2024년 전체에서는 동시 거래 564건 중 486건을 탐지했고 오탐 40건, 정밀도 **92.40%**, 재현율 **86.17%**였습니다. 이 수치는 동시 거래 유형에 한정됩니다. [전문 모델 실험](../reports/bank_concurrent_specialist_strict_experiment.json)에 금액 제외 후보와 개발·후향 평가 결과를 함께 기록했습니다.

일반 모델과 전문 모델 중 하나라도 각 기준을 넘으면 경보를 내는 조합은 기존 일반 모델보다 이상 거래 373건을 더 찾고 정상 거래 경보 35건을 더 냈습니다. 전체 정밀도 **78.53%**, 재현율 **76.93%**, 동시 거래 탐지 **501/564건(88.83%)**으로 개선됐습니다. 전문 모델만의 성능을 전체 이체 성능으로 표시하지 않으며, 두 점수의 최댓값을 사기 확률로 만들지도 않습니다.

명시 실행하는 사후 점검 연구 API에 이 조합을 연결했습니다. 일반·전문 점수, 각 기준과 경보, 두 모델의 해시 기반 버전을 함께 저장합니다. 서버는 점수와 경보의 일치, 모델·보고서의 일치, 원장 관측값을 검사한 뒤 구간을 닫습니다. [조합 보고서](../reports/bank_closed_window_hybrid.json)는 두 파일의 해시와 평가 결과를 묶습니다. 이미 확인한 2024년 합성 라벨에 대한 후향 평가이며 실제 사기나 독립적인 미래 성능을 보장하지 않습니다.

### 다중분류 후보와 남은 미탐

정상과 여섯 이상 유형을 나눠 학습한 [다중분류 후보](../reports/bank_window_multiclass_experiment.json)는 86개 특징을 사용합니다. 거래를 판별할 때 유형 정답을 입력하지 않고 `1 - 정상 클래스 점수`를 출력합니다. 2022년 4분기 개발 구간에서 고정한 기준 0.198932를 유지한 채 과거 3,002,406건 전부로 재학습했습니다. 현재 API에는 연결하지 않았습니다.

[후보 재추론 감사](../reports/bank_window_candidate_audit.json)는 모델 파일 해시, 원본 28개 파일의 지문, 특징 캐시, 같은 평가 모집단과 고정 기준을 확인합니다. 일반·전문·다중분류 파일로 2024년 전체 1,431,700건을 다시 계산한 정탐·오탐·미탐과 유형별 수치가 기존 보고서와 일치했습니다. 이 검사는 보고서의 재현성을 확인하며, 새로운 독립 검증 성능을 만들지는 않습니다.

| 이상 유형 | 평가 건수 | 일반 + 동시 전문 탐지 / 미탐 | 다중분류 탐지 / 미탐 |
| --- | ---: | ---: | ---: |
| 갑작스러운 거래패턴 변화 | 955 | 567 / 388 | 535 / 420 |
| 신규 수신처 거래 | 4,295 | 3,279 / 1,016 | 3,690 / 605 |
| 분할 거래 | 732 | 678 / 54 | 647 / 85 |
| 다중 거래의 동시 요청 | 564 | 501 / 63 | 477 / 87 |
| 거액 입금 후 당일 인출 | 80 | 73 / 7 | 71 / 9 |
| 심야·새벽 대량 거래 | 10 | 7 / 3 | 10 / 0 |

다중분류 후보는 조합 모델보다 미탐 325건을 줄였지만 오탐 630건을 늘렸습니다. 신규 수신처 유형의 탐지는 늘었고 다른 네 유형의 탐지는 줄었습니다. 두 모델이 모두 놓친 이상 거래는 752건이며, 다중분류만 경보를 낸 정상 거래도 1,095건입니다. 한쪽이 경보를 내면 모두 채택하는 방식만으로 정밀도 문제를 해결할 수 없습니다. 심야·새벽 대량 거래의 10/10 탐지도 표본 10건의 결과이며, 95% Wilson 구간은 약 72.25~100%입니다. 모든 상황에서 100% 탐지한다고 해석하지 않습니다.

### 과거 정상 거래로 새 패턴 탐지

학습에 없던 이상 유형도 찾아낼 수 있는지 확인하기 위해 [정상 분포 학습](../reports/bank_normal_profile_protocol.json)을 추가했습니다. 네 시점의 과거 정상 거래 399,640건·1,398,552건·1,998,311건·2,671,115건을 각각 전량 사용했습니다. 기존 XGBoost는 같은 시점의 정상·이상 거래 전량을 학습한 모델을 유지했습니다.

### 여러 특성의 정상 관계와 감독 모델 결합

[다변량 정상 학습](../reports/bank_copula_protocol.json)은 같은 8개 값의 관계를 과거 정상 거래 전량에서 학습합니다. 값을 정상 분포의 순위로 바꾼 뒤 특성 간 공분산을 사용했습니다. 개인 이력이 있는 거래는 8개 값, 없는 거래는 개인 변화 지표를 제외한 5개 값을 사용합니다. 시간대·매체별 관계와 전체 관계를 결합했습니다. 네 모델 모두 원본 행의 대응을 유지해 학습했으며, 저장·복원 점수가 일치했습니다.

[결합 결과](../reports/bank_copula_selection.json)는 기존 감독 모델, 더 깊은 감독 모델, 두 모델의 동일 가중 평균을 각각 정상 관계 점수와 결합한 비교입니다. 평균 점수는 검증된 두 감독 점수의 결합 순위이며 보정된 사기 확률이 아닙니다. 이 비교는 앞선 개발 결과를 보고 설계했으며 독립 검증이 아닙니다.

| 감독 점수 | 정밀도 | 재현율 | 정탐 | 오탐 | 심야 유형 탐지 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 세밀한 구간화 모델 | 90.01% | 67.87% | 3,360 | 373 | 0/23건 |
| 더 깊은 모델 | 90.06% | 66.81% | 3,308 | 365 | 1/23건 |
| 두 모델의 동일 가중 평균 | 90.05% | 68.35% | 3,384 | 374 | 0/23건 |

평균 후보는 앞선 최고 진단 결과보다 정탐 24건·오탐 1건이 늘었습니다. 과거 이력이 없는 이상 거래 15건은 세 구성 모두 놓쳤습니다. 정상 관계 점수만으로는 정밀도 90% 조건을 만족하는 기준을 찾지 못했습니다. 전체 재현율 80%와 유형별 재현율 50%를 함께 만족하는 정책은 여전히 없으며 서버 모델로 적용하지 않았습니다.

### 비선형 정상 분포 학습

[추가 정상 학습 계획](../reports/bank_kernel_protocol.json)은 정상 분포가 하나의 타원 형태로 설명되지 않을 가능성을 확인하기 위한 후보입니다. 과거 정상 값의 순위와 시간대·매체의 범주를 RBF 근사 특징으로 바꾸고, SGD One-Class SVM으로 정상 경계를 학습했습니다. 각 과거 정상 거래를 다섯 번 모두 학습했으며, 개인 이력이 없는 거래에서는 개인 변화 지표를 제외했습니다. 저장한 수치 계수의 판별이 원래 분류기와 일치하고, 저장·복원 후 전체 개발 점수가 일치하는지 확인했습니다.

[공통 기준 결과](../reports/bank_kernel_selection.json)의 최선은 두 감독 모델 평균과 비선형 정상 점수를 결합한 정밀도 90.02%·재현율 68.31%, 정탐 3,382건·오탐 375건입니다. 앞선 다변량 결합 후보보다 정탐은 2건 적고 오탐은 1건 많았습니다. 심야 유형은 0/23건, 이력이 없는 이상 거래는 0/15건이며, 정상 점수 단독으로 정밀도 90%를 만족하는 기준도 없었습니다. 모든 목표를 통과하는 정책이 없어 서버 모델로 적용하지 않았습니다.

256개 근사 특징과 다섯 번의 SGD 학습이 최적 설정이나 수렴을 증명하는 것은 아닙니다. 정상 참조의 꼬리 점수와 학습 파라미터 `nu`를 실제 사기 확률이나 검증된 오탐 비율로 해석하지 않습니다. 같은 과거 개발 정답을 다시 사용한 설계·선택 결과이며 독립 검증이 아닙니다.

원본 데이터와 기존 특징 캐시가 있는 환경에서 아래 명령으로 후보 재추론, 학습 구간 대조와 준비 상태를 다시 확인할 수 있습니다. 첫 두 명령은 모델을 새로 학습하거나 API 모델을 교체하지 않습니다.

```powershell
python scripts/audit_bank_window_candidates.py
python scripts/validate_bank_training_protocol.py
python scripts/audit_model_readiness.py
```

### 모든 과거 관측 구간의 활동 분포

기존 114개 특징에 과거 관측 구간의 활동 분포 28개를 추가해 142개 특징으로 학습했습니다. 출금계좌의 이전 모든 관측 구간과 같은 시간대 구간에서 거래 횟수·총액·수신처 수의 평균, 표준편차, 상대 편차, 순위를 계산합니다. 현재 구간을 과거 분포에 넣지 않으며, 거래가 없던 구간은 임의로 만들지 않습니다. 구간 전체를 관측한 뒤 사용하는 연구 입력입니다.

기존 114개 특징 대조 모델과 같은 XGBoost 설정을 사용했습니다. 네 시간 분할의 학습 거래 400,340건·1,402,810건·2,004,681건·2,679,830건을 각각 전량 사용하고, 800회 학습했습니다. 과거 특징 준비에는 3,002,406건을 사용했습니다. 이 수치는 최종 모델 하나에 모든 과거 거래를 재학습한 결과를 뜻하지 않습니다.

네 개발 구간의 1,337,000건과 이상 라벨 4,951건에 공통 경보 기준을 적용했습니다. 정밀도는 90.04%, 재현율은 68.63%, 경보 비율은 0.28%입니다. 정탐 3,398건, 오탐 376건, 미탐 1,553건입니다. 같은 모집단의 114개 특징 대조 모델은 정밀도 90.00%·재현율 67.82%였습니다. 정탐은 40건, 오탐은 3건 늘었고 재현율은 약 0.81%p 높아졌습니다.

모든 유형이 개선되지는 않았습니다. 분할 거래는 497/669건에서 517/669건으로 늘었지만, 동시 거래는 242/297건에서 233/297건으로 줄었습니다. 거래패턴 변화도 479/924건에서 475/924건으로 줄었고 AP는 0.89153에서 0.89097로 낮아졌습니다. 심야 유형 23건과 과거 이력 없는 이상 거래 15건은 모두 놓쳤습니다. 재현율 80%와 관측 유형별 재현율 50%를 충족하지 못해 선택된 정책은 없으며, 기본 API 모델을 교체하지 않았습니다.

원본 행 순서, 특징·정답·모델·예측 파일의 서명, 저장·복원 점수의 일치와 실제 경보 건수를 확인했습니다. 같은 과거 개발 정답을 다시 사용한 실험이므로 독립 미래 성능이나 실제 사기 탐지 성능으로 해석하지 않습니다. [학습 프로토콜](../reports/bank_window_history_training_protocol.json), [공통 평가](../reports/bank_window_history_selection.json), [건수·희소 사례 검증](../reports/bank_window_history_verification.json)에 근거를 기록했습니다.

이 실험을 재현하려면 승인받은 원본 데이터, 앞선 특징 캐시와 114개 특징 대조 모델의 완료된 학습 결과가 필요합니다. 학습은 `scripts/experiment_bank_window_history.py --all`, 저장된 결과 검증은 `scripts/verify_bank_window_history.py`로 실행합니다. 연구 모델은 기본 실행 모델에 포함하지 않습니다.

## 같은 금액과 다른 결과

같은 금액은 같은 입력을 뜻하지 않습니다. 시간대, 방식, 이전 거래 빈도, 평소 금액 대비, 수신계좌 흐름이 다르면 점수가 달라질 수 있습니다. 모든 특징과 모델 파일이 같다면 같은 점수가 나와야 합니다. 학습 특징, Python 응답, Kotlin 저장 결과의 일치를 단위 테스트와 실제 HTTP 검증으로 확인합니다.

학습 금액 범위는 결제 한도가 아닙니다. 범위 밖 금액, 맥락 부족, 평가 시점 밖 입력은 실제 점수와 함께 검증 범위 제한을 기록합니다. 금액을 최댓값으로 바꾸거나 낮은 점수를 정상 확정으로 바꾸지 않습니다.

## 모델 점수 기여도

입출금 흐름 연구 경로는 원래 분류기의 `predict_proba`를 128개 정보 조합에 실행합니다. 66개 특징을 금액, 거래 조건, 출금 반복, 경과 기간, 당일 출금, 출금계좌 입금, 수신계좌 흐름의 7개 묶음으로 나누고 각 묶음의 평균 점수 기여도를 정확히 합산합니다.

비교 기준은 정상 학습행 전체의 수치 평균과 범주 대표값입니다. 이 기준과 치환 조합은 실제 거래를 뜻하지 않습니다. 연관된 특징, 비교 기준, 정보 묶음에 따라 기여도가 달라지므로 사기 원인의 증명이나 실제 사기 확률로 해석하지 않습니다.

`비교 점수 + 7개 기여도의 합 = 실제 모델 점수`가 성립해야 합니다. API는 특징 중복·누락, 비정상 수치, 점수 불일치를 거부합니다. 설명도 DB에 보존하므로 나중에 조회할 때 새 모델로 다시 만들지 않습니다.

## 실행 범위

연구 후보는 `python scripts\run_demo.py --experimental-bank-v2`로 명시 실행하고 화면에서 입출금 흐름 경로를 선택합니다. 기본 경로와 별도 원장·이력을 사용합니다. 이 옵션은 후보의 운영 성능을 승인하는 설정이 아닙니다.

두 서비스는 로컬 주소에 바인딩합니다. 인증, 실제 금융기관 연결, 식별자 암호화, 다중 서버 동시 운영은 구현되지 않았습니다. 합성 데이터 성능만으로 실금융 서비스의 배포 준비가 끝났다고 판단할 수 없습니다.
