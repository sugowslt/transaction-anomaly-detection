# 문제 해결 기록

재현과 운영 판단에 도움이 되는 문제만 남겼습니다.

## 같은 요청을 재시도했는데 응답 본문이 달라짐

### 증상

중복 저장 방지 테스트에서 첫 판별은 HTTP 201, 재시도는 HTTP 200을 반환했지만 응답 본문 비교에 실패했습니다. 첫 응답의 금액은 `5000000`, 시각은 나노초 단위였고, 저장된 행을 읽은 재시도 응답은 금액이 `5000000.00`으로 표시되고 시각의 정밀도도 달랐습니다.

### 원인

첫 응답은 저장 전 객체를 직렬화하고, 재시도 응답은 H2에서 읽은 값을 직렬화했습니다. H2의 `DECIMAL(19, 2)`와 시각 저장 정밀도가 응답 형식에 반영됐습니다. 해시 열을 `CHAR(64)`로 둔 초기 테스트에서는 짧은 값이 공백으로 채워지는 문제도 확인했습니다.

### 해결

키가 있는 첫 요청도 저장된 행을 다시 읽어 응답하도록 바꿨습니다. 해시 열은 `VARCHAR(64)`로 변경했습니다.

### 검증

Kotlin 테스트 9개가 통과했습니다. 기존 H2 DB의 복사본으로 서버를 실행해 같은 키와 본문을 두 번 보냈을 때 HTTP 201·200의 응답 본문이 같고, 모델 호출은 1회인 것을 확인했습니다. 같은 키에 다른 본문을 보내면 HTTP 409를 반환했습니다.

## 화면은 열리지만 거래 재판별이 되지 않음

### 증상

Kotlin 서버만 실행했을 때 저장된 지표와 가상 거래는 표시됐지만, 화면 상단에 `모델 또는 보고서 연결 필요`가 표시되고 판별 버튼이 비활성화됐습니다. API에 직접 점수를 요청하면 HTTP 503과 아래 응답을 반환합니다.

```json
{"error":"Model service unavailable"}
```

### 원인

Kotlin 서버는 판별 요청을 `127.0.0.1:8001`의 Python 모델 서비스로 전달합니다. 두 프로세스 중 Kotlin 서버만 실행하면 보고서 조회는 가능하지만 새로운 판별은 처리할 수 없습니다.

### 해결

저장소 루트에서 `python scripts\run_demo.py`를 실행해 두 서비스를 함께 시작했습니다. 프로세스를 나눠 실행할 때는 Python 모델 서비스를 먼저 시작한 뒤 Kotlin 서버를 실행합니다.

### 검증

Python 모델이 이체 점수를 반환하고, Kotlin 서버가 판별 결과와 모델 버전을 H2에 저장한 뒤 모니터링 표본 수를 1건으로 갱신하는 것을 확인했습니다.

## Jackson 3에서 JsonNode 순회 코드가 컴파일되지 않음

### 증상

모니터링 기준 분포를 읽는 Kotlin 코드에서 `JsonNode`에 `map`과 `fields()`를 사용하자 다음과 같은 컴파일 오류가 발생했습니다.

```text
Unresolved reference 'size'
Unresolved reference 'fields'
```

### 원인

배열 노드의 `map` 호출이 Jackson 3의 멤버 메서드와 충돌했고, 객체 속성 순회 API도 기존 방식과 달랐습니다. 이 프로젝트는 `tools.jackson.databind` 패키지의 Jackson 3을 사용합니다.

원시 `Map`으로 변환한 뒤 강제 형변환하는 방법도 검토했지만, 잘못된 보고서 구조를 늦게 발견할 가능성이 있어 사용하지 않았습니다.

### 해결

배열은 `values()`, 객체 속성은 `properties()`로 읽도록 변경했습니다. 두 메서드의 동작은 [Jackson 3 `JsonNode` API](https://github.com/FasterXML/jackson-databind/blob/3.x/src/main/java/tools/jackson/databind/JsonNode.java)에서 확인했습니다. 금액 구간 개수와 비율 개수도 함께 검사해 잘못된 기준 보고서가 들어오면 서버 오류로 처리합니다.

### 검증

Kotlin 테스트 6개가 모두 통과했습니다. 실제 Python 모델에 이체를 요청한 뒤 Kotlin 서버가 판별 결과를 저장하고, 모니터링 API가 입력 분포 4개와 모델 버전별 경보 비율을 반환하는 것까지 확인했습니다.

## 소수 셋째 자리 금액이 저장 과정에서 반올림됨

### 증상

H2의 `DECIMAL(19,2)` 열에 `100.005`를 넣자 조회값이 `100.01`이었습니다. 기존 이체 API는 소수 자릿수를 검사하지 않아, 모델에 전달한 금액과 저장 이력의 금액이 달라질 수 있었습니다.

### 원인

입력 검증은 금액의 범위만 확인했고 DB는 소수 둘째 자리까지만 저장했습니다. JSON 숫자를 부동소수점으로 읽으면 아주 작은 초과 자릿수가 사라질 수도 있어, 파싱 결과의 자릿수를 그대로 검사하는 것만으로는 부족했습니다.

### 해결

이체 요청을 읽을 때 Jackson 3의 [`JsonNodeFeature.USE_BIG_DECIMAL_FOR_FLOATS`](https://github.com/FasterXML/jackson-databind/blob/3.x/src/main/java/tools/jackson/databind/cfg/JsonNodeFeature.java)를 사용합니다. 금액의 유효한 소수 자릿수가 둘을 넘으면 모델 호출 전에 HTTP 400으로 거부합니다.

### 검증

Kotlin 테스트 14개가 통과했습니다. `100.005`와 `100.000000000000001`은 거부됐고, `5000000.25`는 모델에 전달한 값 그대로 DB에 저장됐습니다.

## Codex 격리 환경에서 Gradle 다운로드가 막힘

### 증상

2026년 9월 25일 `python scripts\run_demo.py`를 격리 환경에서 실행했을 때 Python 의존성 확인과 모델 서비스 시작은 성공했지만, Gradle wrapper가 `gradle-8.14.5-bin.zip`을 받는 단계에서 `java.net.SocketException: Permission denied: getsockopt`로 종료됐습니다.

### 원인과 해결

첫 실행에 필요한 Gradle 배포 파일을 내려받는 연결이 해당 실행 환경에서 거부됐습니다. 동일 명령을 네트워크 접근이 허용된 환경에서 다시 실행하자 다운로드와 Kotlin 서버 시작이 완료됐습니다. 저장소를 새로 복제한 환경에서도 같은 방식으로 두 서버를 실행했습니다.

### 검증

원본 CSV와 기존 가상환경이 없는 새 체크아웃에서 모델·보고서·가상 거래 검사를 통과했습니다. 로컬 API에서 카드 점수를 받았고, 이체 저장 요청은 HTTP 201, 동일 키 재시도는 HTTP 200을 반환했습니다. 시연 서버와 임시 체크아웃은 확인 후 정리했습니다.
