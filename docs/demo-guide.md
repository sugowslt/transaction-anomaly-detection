# 시연 가이드

이 가이드는 저장소를 실행한 뒤 카드거래와 이체의 모델 판별, 저장 이력, 모니터링을 순서대로 보여주기 위한 것입니다. 화면의 가상 거래에는 정답 라벨이 없습니다. 모델이 `경보`를 반환해도 실제 이상거래라고 증명된 사례는 아닙니다.

## 준비

Windows PowerShell에서 저장소 루트의 `python scripts\run_demo.py`를 실행하고 `http://127.0.0.1:8080`을 엽니다. 첫 실행에는 Python·Gradle 의존성 다운로드가 필요합니다. 화면 오른쪽 위에 `모델·보고서 버전 일치`가 표시되는지 확인합니다. 버전이 다르거나 모델 서비스가 연결되지 않으면 재판별 버튼이 비활성화됩니다.

이체 이력은 로컬 H2에 남습니다. 이미 시연한 환경이라면 처음부터 이력이 보일 수 있습니다. `가상 이체 32건 기록` 버튼은 모델 버전별로 같은 요청 키를 사용하므로, 다시 누르면 새 기록 수가 0건일 수 있습니다. 기존 이력을 지우지 않고 그대로 설명합니다.

## 화면에서 보여줄 순서

1. **문제와 모델 평가:** 카드·이체 모두 2024년 합성 검증 데이터에서 평가했음을 먼저 말합니다. 카드의 정밀도 99.84%와 재현율 34.97%, 이체의 정밀도 44.45%와 재현율 81.24%를 함께 보여줍니다. 한 수치만으로 두 모델의 품질을 비교하지 않습니다.
2. **경보 기준의 선택:** `경보량에 따른 판별 결과`에서 현재 1% 목표 기준과 2% 목표 기준을 비교합니다. 이체의 경우 2024년 검증에서 재현율은 81.24%에서 100.00%로, 오탐은 736건에서 2,083건으로 바뀝니다. 두 기준 모두 2023년 4분기 학습 보류 구간에서 정했고 2024년 검증 데이터에는 적용만 했습니다.
3. **가상 이체 재판별:** `TRANSFER-04`를 선택합니다. 거래금액 5,000,000원, 거래시간대 9에서 저장된 가상 예시의 모델 점수는 약 23.87%이고 정상 판정입니다. 시간대만 6으로 바꿔 `판별하고 기록`을 누르면 현재 포함된 모델에서 약 62.35%와 경보 판정이 나옵니다. 이 결과는 같은 금액·자금구분·매체구분에서 시간대를 바꾼 **모델 응답 예시**이며, 실제 이상거래 여부의 증거가 아닙니다.
4. **백엔드 처리 결과:** `저장된 판별 이력`에서 방금 만든 기록의 점수·판정·모델 버전을 확인합니다. 이 API는 Python 모델 서비스의 응답을 검증한 뒤 Kotlin 서버가 H2에 저장합니다. 같은 `Idempotency-Key`로 재시도한 요청은 중복 저장하지 않습니다.
5. **모니터링:** `가상 이체 32건 기록`을 누르고 최근 입력 분포, 활동일별 추이, 모델 버전별 경보 비율을 보여줍니다. 표본이 30건보다 적으면 변화 상태를 판정하지 않습니다. 여기서의 분포 변화는 입력 특성의 차이이며 모델 정확도나 실제 금융 사기를 검증한 결과가 아닙니다.

## 발표할 때 구분할 내용

- 학습·검증 데이터는 AI Hub의 금융거래 **합성데이터**입니다. 원본 CSV와 원본 행을 가공한 샘플은 저장소에 포함하지 않았고, 화면 시나리오는 별도로 만든 가상 거래입니다.
- 2024년 검증 지표는 정답 라벨이 있는 합성 데이터에서 계산했습니다. 화면의 가상 거래에는 정답 라벨이 없으므로 정밀도·재현율 계산에 넣지 않았습니다.
- 카드 모델의 일부 집계 열과 이체 모델의 자금·매체 구분 코드가 실제 거래 승인 시점에 제공되는지는 확인되지 않았습니다. 따라서 현재 결과를 실거래 운영 성능이나 운영 적용 가능성으로 주장하지 않습니다.
- 발표에서 설명할 구현 범위는 `브라우저 → Kotlin·Spring Boot API → Python 모델 서비스`의 판별 흐름과 `Kotlin API → H2`의 이체 이력 저장·조회입니다. 학습은 별도 Python 스크립트에서 진행했습니다.
